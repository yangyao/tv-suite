# 家庭源管理后台

后台与电视使用同一 HTTP 服务：`/admin` 提供管理页面，`/m3u` 和 `/txt` 提供公开播放列表。没有账号或登录功能，应仅部署在可信家庭局域网内。网页修改操作包含同源与 CSRF 校验。

## Docker 部署

在 `source-manager/` 目录执行：

```sh
docker compose -f compose.manager.yml up -d --build
```

示例配置将端口绑定在宿主机回环地址。需要局域网访问时，在自己的私人 Compose 文件中改为宿主机 LAN 地址，或配置局域网反向代理。不要将管理端口暴露到互联网。

镜像复用上游 `guovern/iptv-api` 的 Python 和 FFmpeg 运行环境，通过 `Dockerfile.manager` 打包当前仓库源码。不会启动上游 Nginx、RTMP 或桌面 GUI。构建时可通过 `BASE_IMAGE` 指定已拉取的上游镜像或固定 digest。

```sh
docker build -f Dockerfile.manager -t tv-suite/source-manager:local .
```

默认数据目录为 `/data`，通过卷持久化。`MANAGER_BIND` 默认 `0.0.0.0:8080`，`MANAGER_DATA_DIR` 默认 `/data`。使用 host 网络时，应将 `MANAGER_BIND` 明确设为局域网地址和端口。

## 迁移现有数据

先备份旧部署。将原来的 `config/` 和 `output/` 复制到新数据目录中，再启动后台：

- 首次启动会将 `config/subscribe.txt` 中的入口导入 SQLite，保留启停状态与 User-Agent。
- 已有的 `output/result.m3u` 会作为初始正式列表，避免迁移时丢失频道。
- 导入后，入口和设置由网页与 `manager.sqlite3` 管理，不再回写旧订阅文件。
- 上游的频道目录作为初始目录，可在“更新设置 → 频道目录”中修改。

## 功能

- 入口：新增、编辑、删除、启停、批量导入，以及连接和列表格式测试。
- 更新：手动触发、间隔更新或北京时间定时更新；同一时间只运行一个任务。
- 检测：复用上游采集与 FFprobe 检测，显示每个入口的候选数、通过数和连续失败次数。
- 频道：按名称和分组筛选，查看线路速率、延迟、分辨率和失败信息；屏蔽线路、隐藏频道或恢复。
- 日志：保留最近 30 次任务及日志，页面显示最近 64 KB。
- 设置：更新周期、并发、超时、清晰度、速率、IPv4/IPv6、每频道线路数量和频道目录。

## 运行与数据一致性

Gunicorn 仅启动一个 worker，提供 4 个请求线程；一个后台执行线程管理队列和调度。每次检测在独立子进程与配置快照中运行，FFprobe 在需要时临时启动。无 MySQL、Redis 或其他独立数据库服务。

任务在 `jobs/<id>/` 中写入临时结果。生成有效列表后，写入不可变发布目录，并通过原子替换 `current` 符号链接发布 M3U 和 TXT。异常、取消或零可用结果均保留上一次正式列表。屏蔽规则会立即重新生成正式列表，也会应用到后续发布；可恢复的原始结果一并保存。

修改设置或入口只影响下一个任务，排队和运行中的任务使用已保存的快照。检查失败的入口不会自动删除或永久停用。服务重启会标记中断任务，执行器异常退出后检测子进程会自行停止；任务记录保存在 SQLite 中。

网页频道页显示最近一轮检测明细，正式发布的频道数量以首页为准。默认频道目录只包含上游预置频道；新增其他频道时，需要在目录中添加对应名称。

## 测试

运行环境相关测试：

```sh
python -m unittest discover -s tests -p 'test_manager*.py' -v
```

集成测试使用本地 HTTP 服务和 FFmpeg 生成的测试视频，验证真实检测、发布和空结果保护，不依赖外部直播源。

完整上游测试还需要 Pipfile 中的桌面 GUI 开发依赖，可使用 `pipenv run python -m unittest discover -s tests -v`。

## 私人数据

数据卷、数据库、日志、家庭地址、个人部署脚本放在 `private/` 或仓库以外。`private/` 已从 Git 和 Docker 构建上下文排除。不要上传数据卷作为公开镜像或构建产物。

## 电视预览

`/preview` 提供独立的频道卡片页，后台右上角也有入口。分类、搜索、台标、线路列表来自当前正式发布的 M3U；屏蔽规则会在刷新后同步生效。打开页面不会自动播放，选择频道后只有一个播放器请求视频。支持上一台、下一台、线路切换、停止、全屏，以及方向键移动焦点、Enter 播放、Page Up / Down 切台和 F 全屏。

默认先由浏览器直连 HLS。遇到失败时，会尝试同源预览转发，再依次尝试其他已发布线路；也可以手动选择直连或转发。转发只用于网页当前的预览，不修改 `/m3u` 或电视配置，不使用 FFmpeg 转码。浏览器自身需要支持源的编码格式。

预览转发只接受正式列表中的频道和线路编号，HLS 内的分片、密钥和子列表改写成会话资源，不接受任意 URL 参数。只访问公开 HTTP / HTTPS 地址，拒绝内网地址和指向内网的重定向。内网源可以选直连。支持播放列表中的 VLC User-Agent / Referer 选项及单段 Range 请求。

资源限制：最多两个转发会话、八个同时读取请求；会话空闲 60 秒或累计 30 分钟后失效，停止和切台会关闭旧连接。播放列表最多 2 MB，单资源最多 32 MB；上游连接超时 4 秒、读取超时 10 秒。管理服务使用一个进程、十二个线程，保留线程供管理请求使用。长时间预览会话过期后可点击重新播放。

播放器依赖随源码提供的 hls.js，页面无需运行时访问 CDN，也不需要安装 Node.js。Python 仍使用镜像原有的 Flask 和 requests，没有新增数据库或常驻服务。
